B. 圃場の仮登録機能 Laravel Flutter DB

現状の圃場登録は「基本情報（圃場名・栽培方式・作物種別）→ 境界設定（GPS区画）」の2ステップが必須。 仮登録機能では、圃場名のみで登録を完了できるようにし、栽培方式・作物種別・境界情報は未入力のまま 測定を開始できるようにする。境界情報がない圃場では、測定時のエリア内外判定（maps_toolkit）を スキップする。

Step B-1：DBスキーマ調査（nullable化）

まずRDS上の farms テーブルの現行スキーマを確認し、NOT NULL制約の有無を特定する。

Step B-2：マイグレーション作成（nullable化のみ）

仮登録かどうかを管理する専用カラムは追加しない。boundary_polygon は 「仮登録中はnull・本登録が完了すると必ず値が入る」という一意な状態遷移をたどるため、 boundary_polygon IS NULL であること自体を仮登録判定の唯一の情報源とする。 カラムと実データの整合性を別途保証する必要がなくなり、更新漏れによる不整合のリスクも生まれない。 必要な変更は既存3カラムのnullable化のみで、スキーマへの追加は一切行わない。 

php artisan make:migration alter_farms_allow_provisional_registration --table=farms
// database/migrations/xxxx_xx_xx_alter_farms_allow_provisional_registration.php
public function up(): void
{
    Schema::table('farms', function (Blueprint $table) {
        $table->string('cultivation_method')->nullable()->change();
        $table->string('crop_type')->nullable()->change();
        $table->json('boundary_polygon')->nullable()->change();
    });
}

public function down(): void
{
    Schema::table('farms', function (Blueprint $table) {
        // cultivation_method / crop_type / boundary_polygon のNOT NULL復元はdown側では省略
        // （既存データにNULLが入っている状態でNOT NULLへ戻すと失敗するため）
    });
}
doctrine/dbal が未導入の場合、->change() はエラーになる。 未導入なら composer require doctrine/dbal を先に実行すること（Laravel 12は非推奨警告が出る場合があるため、 生SQLでの ALTER TABLE ... MODIFY COLUMN ... に切り替えても良い）。

Step B-6：測定画面 — エリア判定ロジックのスキップ

MeasurementSessionScreen のStep3（本測定）における「圃場内外判定（maps_toolkit）→ 圃場外なら測定開始禁止」 のロジックを、選択中の圃場が仮登録圃場（boundary_polygon == null、すなわちAPIレスポンスで境界情報が空）の場合はスキップする。 

// MeasurementSessionScreen 内、圃場内外判定箇所
bool _isInsideOrEdge(LatLng point) {
  final farm = _selectedFarm;
  if (farm == null) return false;

  // 仮登録圃場（境界情報なし）はエリア判定自体を行わない
  // 判定はboundaryPolygonの有無のみで行う（専用フラグは持たない）
  if (farm.boundaryPolygon == null || farm.boundaryPolygon!.isEmpty) {
    return true; // 常に測定可能とみなす
  }

  final containment = PolygonUtil.containsLocation(point, farm.boundaryPolygon!, false);
  final onEdge = PolygonUtil.isLocationOnEdge(point, farm.boundaryPolygon!, 1e-6);
  return containment || onEdge;
}
  • 本測定画面で、赤い圃場境界線が「仮登録圃場では表示されない」ことをUI上でも明示（境界未設定のバナー等）
  • 仮登録圃場選択時は「測定開始」ボタンが常に有効であることを確認
  • 境界情報がある通常の圃場では、従来通り圃場外判定が機能することを回帰確認
仮登録圃場はGPS判定を行わないため、誤って別の畑で測定してしまうリスクがある。 測定開始前の確認ダイアログに「この圃場は仮登録のため、位置情報による誤測定防止が働きません」の注意文言を追加することを推奨する（必須ではないが強く推奨）。

C-2. 圃場平均ロジックの変更（最新日平均 → 全日付平均の平均）

現状の挙動： 圃場平均として「最新の測定日における全測定点の平均値」を表示している。

変更後の挙動： 各測定日ごとの平均値を算出し、それら日付別平均の単純平均を「その圃場の平均値」として算出。グラフ上には、この1つの値を水平な1本の点線として表示する（日付ごとに値が変化する折れ線ではない）。

例：日付1（7点測定）→ 日平均A、日付2（5点測定）→ 日平均B、日付3（7点測定）→ 日平均C　のとき、 圃場平均 = (A + B + C) / 3。点数の重み付けは行わず、日付単位の平均をさらに平均する。

Laravel側：ResultsAggregationService の修正

// app/Services/ResultsAggregationService.php

/**
 * 圃場平均（日付別平均の平均）を算出する。
 * 日付別平均はあくまで内部の計算過程であり、APIとしては最終的な
 * farm_average（1つのfloat値）のみを返す。グラフには水平点線として描画する。
 */
public function computeFarmAverage(int $farmId, string $parameterName = 'CEC'): ?float
{
    $dates = AnalysisResult::query()
        ->whereHas('upload', fn ($q) => $q->where('farm_id', $farmId)->where('status', 'completed'))
        ->join('uploads', 'analysis_results.upload_id', '=', 'uploads.id')
        ->selectRaw('uploads.measurement_date as date')
        ->distinct()
        ->orderBy('date')
        ->pluck('date');

    $dailyAverages = [];
    foreach ($dates as $date) {
        $avg = ResultValue::query()
            ->where('parameter_name', $parameterName)
            ->whereHas('analysisResult.upload', fn ($q) => $q->where('farm_id', $farmId)->where('measurement_date', $date))
            ->avg('parameter_value');
        if ($avg !== null) {
            $dailyAverages[] = round($avg, 2);
        }
    }

    if (empty($dailyAverages)) {
        return null;
    }

    return round(array_sum($dailyAverages) / count($dailyAverages), 2);
}
圃場平均は、時系列グラフの横軸全体を通じて水平な1本の点線として表示する（日付ごとの平均点を結ぶ折れ線ではない）。 グラフ上の各データ点（固定地点の実線・フリー地点の点）とは独立した、圃場全体の代表値を示す固定値ラインとして扱う。

Step C-3-1：圃場中央値（重心）算出ロジック

// app/Services/PolygonCentroidService.php（新規）
class PolygonCentroidService
{
    /**
     * 圃場のboundary_polygon（正規化済み配列）から単純重心を算出する。
     * 農地は小規模のため、緯度経度の単純算術平均で十分な精度とする。
     */
    public function centroidOf(array $normalizedPolygon): array
    {
        $count = count($normalizedPolygon);
        $latSum = array_sum(array_column($normalizedPolygon, 'lat'));
        $lngSum = array_sum(array_column($normalizedPolygon, 'lng'));

        return [
            'latitude'  => round($latSum / $count, 7),
            'longitude' => round($lngSum / $count, 7),
        ];
    }
}
仮登録圃場（B項目で追加した boundary_polygon = null の圃場）は重心を算出できないため、 過去実績の手動入力対象からは除外する（フォームの圃場選択肢に出さない、もしくは選択時にエラー表示）。

// app/Http/Controllers/ManualResultController.php（新規）
public function store(StoreManualResultRequest $request, PolygonCentroidService $centroidService)
{
    $farm = Farm::findOrFail($request->farm_id);

    if (empty($farm->boundary_polygon)) {
        return response()->json(['message' => 'farm_boundary_required'], 422);
    }

    $centroid = $centroidService->centroidOf(
        PolygonNormalizer::normalize($farm->boundary_polygon)
    );

    return DB::transaction(function () use ($request, $farm, $centroid) {
        $upload = Upload::create([
            'farm_id'                => $farm->id,
            'measurement_date'       => $request->measurement_date,
            'measurement_parameters' => ['manual_entry' => true],
            'file_path'              => null,
            'status'                 => 'completed',
        ]);

        $analysisResult = AnalysisResult::create([
            'upload_id'   => $upload->id,
            'sensor_info' => ['manual_entry' => true],
            'latitude'    => $centroid['latitude'],
            'longitude'   => $centroid['longitude'],
        ]);

        foreach ($request->values as $paramName => $value) {
            if ($value === null || $value === '') {
                continue;
            }
            ResultValue::updateOrCreate(
                ['analysis_result_id' => $analysisResult->id, 'parameter_name' => $paramName],
                ['parameter_value' => $value, 'unit' => SoilParameterUnits::unitFor($paramName)]
            );
        }

        return response()->json(['upload_id' => $upload->id], 201);
